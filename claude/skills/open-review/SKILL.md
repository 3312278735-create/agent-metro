# 去验收：替用户打开验收界面

进度卡（`<看板目录>/progress-card/card.js`）上橙色的「待你验收 ↗」是按钮：点某一站 = 用户发「去验收 T0xx」；在总看板汇总卡上点某条线的「待你验收 N ↗」= 用户发「我要验收 <项目名>」。

## 最要紧的一条：不经同意，一个窗口都不开到桌面

所以：**点「去验收」≠ 同意开窗口**。游戏、编辑器、浏览器、资源管理器、文档……任何会在桌面上弹出来的，都要他这一次明确同意（回「开到桌面 T0xx」或点卡上「同意，开到桌面 ↗」）才开。对照图、截图用 `SendUserFile`（display: render）在对话里给他看，不算上桌面。

## 收到「去验收 T0xx」

1. 跑 `node "<看板目录>/tools/open-review.js" T0xx`（**默认只准备，不开任何窗口**）。
   它按总看板项目页 `projects/<项目名>.md` 里「## 验收怎么打开」一节检查文件、服务、Godot 能不能开，列出「同意后会开什么」，再打印这站在「待你验收」里的原文。
   - 输出里的「给用户看的对照图」→ 用 `SendUserFile` 在对话里发给他（display: render），不要开浏览器。
   - 输出里有「手机上打开：…」的，把那个地址原样给用户（不要缩写）。
   - 进度卡 `check` 里加 `show`：列出同意后会开到桌面的东西（例 `["对照页（浏览器）", "游戏：直接进第 1 个岛", "安装包文件夹"]`），卡上会出「同意，开到桌面 ↗」按钮。
   - **退出码 2**：这站还没登记怎么打开。照打印出的验收步骤，能打开的你自己打开（PowerShell `Start-Process`），再把打开方式补进项目页「验收怎么打开」（写法见 `<看板目录>/PROTOCOL.md` 3.1 第 4 条）。要另一台电脑、外部账号才能验的，只给步骤。
   - **退出码 1**：出错了（路径过期、找不到 Godot……）。用大白话告诉用户原因，能修就把项目页里那一行改对再跑一次。
   - 输出里有「⚠ 这站没有对照图」：如实告诉用户这站是凭文字验收的，并在回复里说明会补（有界面的站按规矩本该先交对照图，见 PROTOCOL 3.1 第 5 条）。
2. 回复用户，**必须带验收标准**：
   - 一句话说开了什么、对照图怎么看（左示意图、右实拍）。
   - **验收标准分三块**，进度卡 json 的 `check` 也按这三块写，卡上画成带勾选框的「验收标准」框：
     ```json
     {"task":"T0xx",
      "items":[{"text":"验什么（一句话）","do":"怎么做：打开哪里、点什么","see":"应该看到：具体到文字/颜色/数字（卡上和 do 合成一行「怎么验」；不写不对的样子）","why":["作用：这一条的目标，做成了能得到什么，讲给小白听"]}],
      "decide":[{"text":"要你拍板的事","advice":"我的建议","reply":"回「留」或「加回来」","why":["来龙去脉"]}],
      "verified":["我替你查过的，不用你验，只是告诉你"]}
     ```
     - `items` 只放**用户能动手做的**：没有「怎么做 + 应该看到」的不是标准，是事实，放 `verified`。
     - `decide`：AI 自己做的决定要如实写「这是 AI 定的，你没说过」，不能写成「你定的 / 你担心的」（#T094 撤 2 条就被写成了用户的意思，记录里查无此话）。
     - 引用任何规矩 / 红线当理由时，写清**出处**（哪份文档、谁写的、原话）和 **AI 有没有收严**；用户文档里没有、是 AI 加的，就明说「这是 AI 加的」。
     - `why` 讲给小白听，**而且只回答「为什么要验这个」**——三句：这东西是什么 / 验它防的是什么问题 / 不验会怎样；术语第一次出现用括号解释或配例子（「代称词：视频里不能直说的词换的说法，比如『玫瑰』= 玫瑰痤疮」）。顺带要说的话（数字对上了、某个字过时了）放 `note`，卡上另起一行「顺带：…」，别塞进 why。
     - 全部大白话：不贴程序原文、字段名、英文（`就绪 true`、`{"ok":true…}` 用户说看不懂）。
   - 项目页「待你验收」写得不像这样，就由你整理成这样（并顺手把项目页改了）。
   - 最后一行：动手验的都对、拍板的回了 → 回「完成 T0xx」；有一条不对直接说第几条。
   照常出进度卡。

## 收到「开到桌面 T0xx」（他同意了）

跑 `node "<看板目录>/tools/open-review.js" T0xx --show`，这一次才真的开到桌面。只开这一站登记的东西；开完告诉他开了哪几个窗口、关掉就行。同意只管这一次，下一站、下一次还要再问。

## 收到「我要验收 <项目名>」

出这个项目的卡：`card.js --project <项目名>`。卡上每个待验收的站都带「待你验收 ↗」按钮，用户再点具体哪一站。回复里一两句说这条线有几站等验收、各是什么。

## 用户验收时说「不对 / 和图不一样 / 没做到」

1. 立刻 `node "<看板目录>/tools/ledger.js" set-status T0xx doing "<用户原话>"`——站退回进行中，原话进看板 HISTORY.md。
2. 把原话写进项目页「待你验收」那一条下面：`  - 验收反馈 MM-DD：……`。
3. 去修（在项目会话里就直接修；在看板会话里就派回去）。修完必须重新出对照图、自己逐块对过，才 `set-status T0xx review`。返工期间不要挂着待验收。

## 注意

- 窗口只在他同意（「开到桌面 T0xx」）后用 `--show` 开到桌面；没同意之前一个都不开。AI 自己跑测试、截图的窗口照旧放屏幕外（上下挪，不左右挪）。
- 「服务」类只在没开时才开，不重启用户正在用的服务；要重启先问。
- Unity、UE 的站暂时不能自动打开，按退出码 2 的办法处理。
- 在哪个项目的会话里收到都照这样做。脚本只读看板；补项目页那一行、改状态都算上报，按 `PROTOCOL.md` 办。
