# 粘进 `~/.claude/CLAUDE.md` 的规则片段

> 用法：把下面「---」之间的内容粘进你的 `~/.claude/CLAUDE.md`（没有就新建），把所有 `<看板目录>` 换成你放本仓库的路径，例如 `D:/看板`。
> 想要哪几条就留哪几条；进度卡、传送带都可以不用。

---

## 先读项目里的 AGENTS.md

项目里的 AI 协作规则可能写在 `AGENTS.md`（Cursor、Trae 等工具读它），而不是 `CLAUDE.md`。开工前，当前项目根目录有 `AGENTS.md` 就先读并遵守；两者冲突时以 `CLAUDE.md` 为准。

## 跨项目总看板

我所有项目的进度汇总在 `<看板目录>`（总看板）。

- 判断当前项目有没有登记：看 `<看板目录>/projects/*.md` 里哪个文件的 `path:` 与当前工作目录一致。没有匹配就是没登记——不要自己新建项目页，告诉我「这个项目还没在看板登记」。
- 登记过的项目：我问进度时，末尾附一段「总看板对照」；阶段性收工、任务状态变化或被阻塞时，**先**更新项目内进度，**再**按 `<看板目录>/PROTOCOL.md` 上报。
- 纯问答、小改动、没有改变任务状态的会话不用上报。
- 当前工作目录就是总看板本身时，忽略本节，按那里的 `CLAUDE.md` 办。
- 看板目录不存在或无权访问时，跳过并告诉我，不要因此中断手头的工作。

## 每次回复末尾附进度卡

每次回复的最后附一张进度卡，让我随时看到你在做什么、接下来做什么、要我关注什么。

- **怎么出**：用 bash 跑

  ```
  node "<看板目录>/progress-card/card.js" <<'EOF'
  {"doing": {"task": "T005", "text": "……"}, "next": [...], "you": [...]}
  EOF
  ```

  - `doing`：正在做的事；`next`：接下来 2～4 步；`you`：要我关注的，每条 `{"task", "title", "text"}`，最急的排第一。
  - `asks`：我这次派的活，每条 `{"task", "text", "done"}`，`done` 写 `true` / `"doing"` / `false`。
  - `next`、`you` 里你自己建议、不是我派的，加 `"ai": true`（卡上置灰、收进折叠）。
  - `names`：给传送带上的站起 4 个字以内的短名，例如 `{"T118": "按钮挪位"}`。
  - `check`：有待我验收的站时带上验收标准（见下一节），卡上画成带勾选框的框。
  - 只有 PowerShell 时，先把 json 存成文件，再 `node "<看板目录>/progress-card/card.js" <文件>`（PowerShell 往 node 管道里传中文会变成问号）。
- **怎么显示**：有 `show_widget`（可视化组件）就把脚本输出原样交给它；没有（比如在终端里）就加 `--text`，把输出的几行字贴在回复最后。
- 只关心一个项目时加 `--project <项目名>`。脚本只读看板，读不到也照常出卡。

## 待验收：要有标准

- **不是每个改动都要我验收**：结果你自己查得到（测试、命令、数据）或不太紧要的站，查完跑 `node "<看板目录>/tools/ledger.js" set-status T0xx done "自查：查了什么"`，台账记「自动验收」。有界面、要看手感、要我拍板、重要的站才转待验收（`set-status T0xx review`）。
- **有界面的站，转待验收前先交对照图**：你的实拍和我认可过的示意图并排放一页，自己先逐块对、不一样的先改。只跑通测试没看图不算自测过。
- **验收标准分三块**：「要你动手验的」每条写 作用（做成了能得到什么）+ 怎么验（怎么做、应该看到什么）；「要你拍板的」写清建议和我回什么，你自己定的事别写成我定的；「我替你查过的」只告诉我。不贴程序原文、字段名。
- **我说「完成 T0xx」**：`set-status T0xx done --me`（记人工验收）。
- **我说哪里不对**：那站立刻 `set-status T0xx doing "<我的原话>"` 退回进行中，修完重新出对照图才回待验收。
- **我说「去验收 T0xx」**：用 `open-review` 技能——先只准备、一个窗口都不开，对照图在对话里给我看，给验收标准；我回「开到桌面 T0xx」才开窗口。

## 到点翻篇 + 传送带

到了时间点某个功能就翻篇，不无休止地打磨。命令都是 `node "<看板目录>/tools/ledger.js"`，下面简写成 ledger。

1. **排站就给预算**：小站半小时、中站 1 小时、大站 2 到 3 小时。预算是「最多花多久」。`ledger set-budget T0xx 1h`。要我审定的再加 `ledger set-ask T0xx <日期>`，站上写好「不回就按 X 做」。
2. **开工才计时，验收期两天**：转进行中时到点自动定成「现在 + 预算」；转待验收时自动定成两天后。手动改：`ledger set-due T0xx +1h`。
3. **会话开始先巡检**：`ledger belt`（只读）。
4. **到点就翻篇**：
   - 你的站到点：当场收尾，能到站的到站（要我验的转待验收），没做完的拆成新站排到线尾，并在回复里写「传送带自动处理了：……」。我说「延期 T0xx」可以延一次。
   - 等我验的站：过期没验就落进验收筐，不挡后面的站，你照常做后面的。不替我判通过（能自动验收的除外）。
   - 等我审定的站：过了期限按站上写好的默认方案开工。
   - 仍然等我的例外：要删东西、花钱、对外发东西的。
5. **新意见另开站**：验收只按开工时定下的标准打勾，新想法记成新站排到后面。
6. **返工最多两轮**：同一站第三次被退回，停下来问我怎么办。

## 附：项目里的「总看板联动」模板

在每个登记项目的 `AGENTS.md` 里加这一节（改项目名、路径、项目内进度文件）：

```markdown
## 总看板联动（跨项目进度）

- 本项目登记在跨项目总看板 `<看板目录>`，看板里的项目名是「示例游戏」。
  - 本项目在看板的页面：`<看板目录>/projects/示例游戏.md`
  - 看板任务行在同目录 `TODO.md` 里，以 `示例游戏｜` 开头，编号形如 `#T005`。
- **项目内进度仍以本目录为准**（`STATUS.md`）。总看板只做粗粒度汇总，不要把看板内容整份抄进来。
- 用户问进度时：先按本目录文档回答，末尾追加一段「总看板对照」。
- 阶段性收工、任务状态变化或被阻塞时：**先**更新本目录的进度文档，**再**按 `<看板目录>/PROTOCOL.md` 上报到看板。在本目录文档里引用看板任务写作 `看板#T005`。
- 看板目录不存在或无权访问时，跳过看板相关动作并告知用户，不要因此中断本项目的工作。
```
